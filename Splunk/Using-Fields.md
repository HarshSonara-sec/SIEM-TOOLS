# Splunk — Using Fields

## Overview

Fields are one of the most important concepts in Splunk. They allow analysts to identify, filter, search, and analyze specific pieces of information contained within events.

Examples of common fields:

* `src_ip` — Source IP address
* `dest_ip` — Destination IP address
* `src_port` — Source port
* `dest_port` — Destination port
* `user` — Username
* `host` — Host that generated the event
* `action` — Action performed
* `status` — Status/result of an event

---

## 1. What is a Field?

A field is a named piece of information extracted from an event.

Example event:

```text
src_ip=192.168.1.10 dest_ip=10.0.0.5 action=blocked user=admin
```

Splunk can identify:

```text
src_ip     → 192.168.1.10
dest_ip    → 10.0.0.5
action     → blocked
user       → admin
```

Fields make raw event data easier to search and analyze.

---

## 2. Search Using Fields

Fields can be used directly in SPL searches.

```spl
src_ip=192.168.1.10
```

Find events generated by a particular host:

```spl
host=web-server
```

Find events involving a particular user:

```spl
user=admin
```

Multiple field conditions can be combined:

```spl
src_ip=192.168.1.10 action=blocked
```

This is useful when investigating security events because an analyst can quickly narrow thousands of events down to relevant activity.

---

## 3. Field Values

A field can contain one or more values.

For example:

```text
action=allowed
action=blocked
```

A search can target a specific value:

```spl
action=blocked
```

Wildcard searches can also be useful:

```spl
user=admin*
```

---

## 4. The `table` Command

`table` displays selected fields in a tabular format.

```spl
| table src_ip dest_ip action user
```

This is useful for making search results easier to read during investigations.

Example:

```spl
index=security
| table _time src_ip dest_ip user action
```

---

## 5. The `fields` Command

The `fields` command controls which fields are included in search results.

Show specific fields:

```spl
| fields src_ip dest_ip user
```

Remove a field:

```spl
| fields - _raw
```

This can help reduce unnecessary information when working with large datasets.

---

## 6. The `rename` Command

Fields can be renamed to make search results easier to understand.

```spl
| rename src_ip AS "Source IP"
```

Multiple fields can be renamed:

```spl
| rename src_ip AS "Source IP", dest_ip AS "Destination IP"
```

---

## 7. The `dedup` Command

`dedup` removes duplicate values based on a field.

```spl
| dedup src_ip
```

This can be useful when identifying unique sources during an investigation.

Example:

```spl
index=security
| dedup src_ip
| table src_ip
```

---

## 8. The `stats` Command with Fields

Fields can be aggregated using `stats`.

Count events by source IP:

```spl
| stats count by src_ip
```

Count events by user:

```spl
| stats count by user
```

Count events by source IP and action:

```spl
| stats count by src_ip action
```

This is particularly useful for SOC investigations.

Example use case:

> Identify which source IP generated the largest number of blocked events.

```spl
index=security action=blocked
| stats count by src_ip
| sort - count
```

---

## 9. Common SOC Uses of Fields

Fields are frequently used to investigate:

* Source and destination IP addresses
* User activity
* Authentication events
* Network connections
* Malware alerts
* Firewall actions
* Failed logins
* HTTP requests
* Endpoint activity
* Security alerts

Example failed-login investigation:

```spl
index=security action=failure
| stats count by user src_ip
| sort - count
```

This can help identify users or IP addresses associated with repeated authentication failures.

---

## 10. Important Field Types

Common Splunk field categories include:

### Default Fields

Fields automatically available in Splunk events.

Examples:

```text
_time
_host
_source
_sourcetype
_index
_raw
```

### Extracted Fields

Fields extracted from event data.

Examples:

```text
src_ip
dest_ip
user
action
status
```

### Calculated Fields

Fields created or derived using SPL commands or configurations.

---

## 11. Useful Commands

| Command  | Purpose                         |
| -------- | ------------------------------- |
| `table`  | Display selected fields         |
| `fields` | Include or exclude fields       |
| `rename` | Rename fields                   |
| `dedup`  | Remove duplicate field values   |
| `stats`  | Calculate statistics            |
| `sort`   | Sort search results             |
| `where`  | Filter results using conditions |

---

## SOC Analyst Takeaway

Understanding fields is essential for Splunk-based SOC work.

A typical investigation often follows this pattern:

```text
Raw Events
   ↓
Identify Important Fields
   ↓
Filter/Search Fields
   ↓
Aggregate with stats
   ↓
Sort/Compare Results
   ↓
Investigate Suspicious Activity
```

The most important fields for a SOC analyst to become comfortable with are:

```text
_time
src_ip
dest_ip
src_port
dest_port
user
host
action
status
```

Fields turn large volumes of raw log data into information that can be searched and investigated efficiently.

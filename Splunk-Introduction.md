# Splunk — Introduction

## What is Splunk?

Splunk is a platform used to collect, search, analyze, visualize, and monitor machine-generated data.

In security operations, Splunk can be used as a **SIEM platform** for centralized log analysis, security monitoring, detection, and investigation.

---

# Machine Data

Machine data is data generated by systems, applications, devices, and infrastructure.

Examples:

- Windows Event Logs
- Linux logs
- Firewall logs
- Web server logs
- Authentication logs
- Application logs
- Network device logs
- Security tool logs

---

# Splunk in a Security Environment

A SOC may receive logs from many different systems.

Instead of manually checking each system, logs can be centralized and searched in Splunk.

```text
Windows ──────┐
Linux ────────┤
Firewall ─────┤
EDR ──────────┼──→ Splunk
Network ──────┤
Applications ─┘
```

Splunk can then help analysts search and investigate the collected data.

# Core Splunk Concepts

## Event

An **event** is a single piece of machine-generated data.

Example:

```text
User failed to authenticate
```

---

## Index

An **index** is a repository used by Splunk to store data.

Example:

```spl
index=windows
index=network
index=security
```

---

## Source

The **source** identifies where the data originated.

Example:

```text
/var/log/auth.log
```

---

## Sourcetype

The **sourcetype** identifies the format or type of data.

Example:

```spl
sourcetype=access_combined
```

---

## Host

The **host** identifies the machine that generated the event.

Example:

```spl
host=web-server01
```

---

# Basic Searching

Search an index:

```spl
index=main
```

Search events from a specific host:

```spl
index=main host=server01
```

Search by sourcetype:

```spl
index=main sourcetype=access_combined
```

Search for a keyword:

```spl
index=main error
```

---

# Fields

Splunk can extract fields from events.

Common examples include:

```text
src_ip
dest_ip
user
action
status
host
source
sourcetype
```

Fields make searching and filtering events easier.

Example:

```spl
index=security src_ip=10.10.10.50
```

# Splunk for SOC Investigation

A SOC analyst can use Splunk to investigate questions such as:

- Which user performed an action?
- Which host generated the event?
- Which source IP was involved?
- How many failed logins occurred?
- What happened before an alert?
- What happened after an alert?
- Which systems were affected?
- Is there a suspicious pattern?

# Security Analyst Mindset

Learning Splunk is not only about memorizing SPL commands.

The important skill is understanding:

```text
Security Question
       ↓
What data can answer it?
       ↓
Find the relevant logs
       ↓
Write a search
       ↓
Filter and analyze results
       ↓
Build evidence
       ↓
Document the conclusion
```

Splunk should be treated as an investigation and analysis tool, not simply as a search interface.
